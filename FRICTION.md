# Friction Log — what a learning companion would have caught

Format: [date] [stage] what stalled me, what I was missing, what would have unblocked me faster.

<!-- log every stall, even small ones — this is user research for the companion idea -->

[Aug 14] [micrograd — derivative definition] Stalled ~1h on the formula (d(c+h) − d(c))/h. Root causes, found only after many rounds of re-asking: (1) read d(c+h) as multiplication, not "evaluate d at c+h" — didn't know math function notation IS a function call; (2) letter collision — d used as both the output's name and in dd/dc notation, c as both the parameter slot and the variable. Unblocked by: concrete numbers first (e=2, c=3, h=0.001), then "def d(c): return c + e — now what's d(c+h)?" — programming framing landed instantly. Categories: prerequisite gap; repeated follow-up questions; AI gave too much detail before finding the actual gap.

[Aug 14] [micrograd — notebook ghost bug] draw_dot(L) crashed with 'float' has no _prev, but the class on screen was correct. Cause: stale kernel state — L was built by an older buggy version of the class; fixed the code, never rebuilt the object. Fixed by Restart + Run All. Category not in the protocol's list: state desync between what's on screen and what's in memory. A companion watching the session would have seen the class redefined after L was created and said so. (Also: this is the .ipynb tax — a .py run top-to-bottom can't desync from itself.)

[Aug 14] [micrograd — backward()] Hit the blank page and asked the AI for "boilerplate" for backward() — i.e., asked it to do the exercise. Caught only because the no-code rule was pre-committed in HYPOTHESIS.md. This is the protocol's own category: "people mainly want AI to finish the work rather than help them learn" — felt the pull firsthand. What I actually needed was the Python closure syntax (a prerequisite), not the algorithm.

[Aug 14] [micrograd — writing the closures] WORKAROUND FOUND: translating math to code was hard until I hand-wrote the name mapping (a = self, b = other, c = out) and drew the flow diagram on paper as a reference. Worked immediately. Why: the stall was juggling two naming systems in my head — externalizing the mapping freed working memory for the logic. Same root cause as the derivative-notation stall (representation collision). Companion implication: a tool could auto-generate and pin exactly this — "here's the mapping between the video's math symbols and your code's variable names" — the moment you start implementing something you just watched. Protocol categories: workaround created; small tool I naturally wished existed.

[Aug 14] [micrograd — closures] Wrote `out._backward = _backward()` (with parens) in all three ops — called the function at build time and stored its return (None). Crash surfaced later as TypeError: 'NoneType' object is not callable, at the CALL site, far from the bug's home at the STORE site. Concept gap: function-as-value vs function-call — "hand over the machine" vs "run the machine." Lesson: the traceback shows where it hurt, not where it happened.

[Aug 14] [micrograd — backward design] Called o._backward() once and expected the whole graph to fill. Missing mental model: each _backward pushes gradient exactly ONE step; something must schedule ALL of them in order (topological sort). The video's split between _backward (one gear) and backward() (the crank) wasn't obvious until I hit it. Resolved with hints, then wrote the topo sort myself.

[Aug 14] [micrograd — stale state, SECOND bite] Fixed = to += in the class cell, saved, tested a+a — still got 1.0 and concluded "it's not accumulating, there is no trade off." Wrong: never reran the class cell, kernel still held the old class. Same disease as the morning ghost bug, opposite direction (fresh code, stale objects vs fresh objects, stale code). TWICE IN ONE DAY = this is a recurring category: on-screen code vs in-memory state desync. A companion that diffs "cells edited since last executed" would have caught both instantly.

[Aug 14] [micrograd — __pow__ type slip] Wrote other.data in the closure two lines under my own assert declaring other is int/float. Would have crashed only at backward() time, deep in a future training loop — closure captured the bug and sat on it. Cousin of the naming-collision family: `other` is a Value in add/mul but a raw number in pow, same name, different species per method.

[Aug 15] [MLP — comprehension slots] Layer.__init__: wrote range(nin) where nout belonged — the "what to build" slot and the "how many times" slot of a comprehension were not separate concepts in my head. Took THREE explanations + a diagram + seeing the wrong output shape before it stuck. Mnemonic that landed: "nin shapes the neuron, nout counts the neurons." Categories: repeated follow-up questions; concept I didn't know I was missing.

[Aug 15] [MLP — zip silently truncates] The mis-built network (3-neuron first layer feeding 4-weight neurons) ran WITHOUT ANY ERROR — zip quietly dropped the extra weight. Wrong math, clean output; only the final output's SHAPE (4 values where 1 belonged) revealed it, two abstraction levels later. Why real frameworks shape-check everything. Category: trusted something I didn't understand — the code ran, so I assumed it was right.

[Aug 15] [prerequisite gaps surfaced by building] Had to stop and ask: what IS w·x+b (answer: y=mx+b in n dimensions, weights=how much each input matters, bias=baseline); what IS parameters() (the list of live knob references, not a count, not data — roles live in the forward pass, the update treats all knobs identically); what is n (the MLP instance). None of these blocked WATCHING the video — all of them blocked BUILDING. Building is the only reliable gap detector I've found.

[Aug 15] [THE BOUNDARY BUG, both directions in one day] (1) Loss: wrote (x.data - y)**2 — numerically correct float, but .data severed the graph; loss had no ancestry, backward impossible. (2) Update: wrote p += -step*p.grad — Value arithmetic built a NEW object and rebound the loop variable; real knob untouched, loss frozen constant for 20 iterations, no error. Same Value/.data boundary, crossed wrongly in both directions, both failures SILENT. Rule extracted: graph-land for anything needing gradients; .data-land only for reading results and nudging knobs. This is PyTorch's .item()/.detach() trap and the in-place-update trap, met in miniature.

[Aug 15] [honest accounting] The operator convenience family (__neg__, __sub__, __radd__, __rmul__, __truediv__, final __pow__ polish) was transcribed from the open reference after the forecast crash, not written from memory. Legal per protocol (struggle first, reference after), logged for the Friday gate.

[Aug 15] [MILESTONE — it trains] Full loop working: loss 6.57 → 0.043 over 20 steps, monotonic. My engine, my MLP, my loop, no framework. 41 parameters confirmed by count. The falling column is the week's first real trophy.
